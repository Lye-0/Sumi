# 開発ガイド

利用者向けの操作説明は [README](../README.md) を参照してください。

## ビルドとテスト

Windows 11と.NET 10 SDKを使用します。追加のNuGetライブラリ依存はありません。

```powershell
./scripts/dev.ps1
./scripts/dev.ps1 -BuildOnly
dotnet run --project tests/Sumi.Tests
# 実モデルを使う場合のみ、Ollamaとgemma4:12bが必要
dotnet run --project tests/Sumi.Tests -- --live
dotnet run --project tests/Sumi.Tests -- --live-multi
```

`dev.ps1`はリポジトリ内の`.dev-data`、Debug版を直接起動すると実行ファイル横の`.dev-data`を使用します。
Release版は通常`%LOCALAPPDATA%/Sumi`を使用します。`--data-dir <directory>`または`SUMI_DATA_DIR`で変更できます。
開発用の配置先を恒久的な設置先として記録しません。インストーラー・自動起動・サービス・タスクスケジューラ・PATH変更は実装していません。

## モデル連携

- `IModelProvider`を境界に、モデル連携をUI・撮影処理から分離しています。
- SumiはOllamaのHTTP APIを直接呼び出さず、`ollama ls`／`show`／`run`／`stop`を使用します。
- 起動は`ollama run <モデル>`の既定設定。effort・think・keepaliveは上書きしません。
- 指示と画像パスはUTF-8の標準入力に渡し、シェルは起動しません。複数画像は撮影順に渡します。
- 子プロセスの接続先をローカルに固定し、クラウドモデルと自動ダウンロードを拒否します。
- 事前準備は空の標準入力を閉じた`run`です。終了時は所有するCLI子プロセスを回収します。
- モデル解放付き終了では、このセッションで準備・使用したモデルに`stop`を実行します。Ollama本体は停止しません。

思考は`Thinking...`／`<think>`形式を回答と分離します。未知のCLI出力形式には追加検証が必要です。
回答本文がない場合の再試行は1回までで、待機上限は両方の実行を通じて共通です。

## UIと診断

ガラス調の外観はWPF内のグラデーションと半透明レイヤーで描画し、ウィンドウ背景は不透明です。
デスクトップ背景のぼかしには依存しません。キャプチャの座標は物理ピクセルで扱います。

Debug版の`--ui-test`は、通常タスクバーに出ない範囲選択・回答ウィンドウをUI検証ツールから列挙できるようにします。
描画・撮影・推論処理は通常と共通で、Release版では無効です。
Debug版は開発データフォルダーに状態・エラーの`development.log`を記録します。指示文・回答本文は記録しません。

## 検証範囲

2026-09-17時点で、自動チェック93項目が通過しています。矩形座標、ショートカット、設定保存、CLI入出力、キャンセル時の子プロセス終了、思考分離、再試行、ストックの順序、最小通知の高さ、トレイ状態、埋め込みアイコンなどが対象です。

Ollama 0.34.0／0.34.1とgemma4:12bで、合成画像の読み取りと複数画像の一括送信を検証しました。
実画面では通常・逆方向ドラッグ、ライト／ダーク、常駐、設定入力、ストック、モデル解放、一時画像削除などを確認しています。

次の点は追加の実機検証が必要です。

- 異なるDPIの複数画面をまたぐ撮影、HDRの色再現、途中での画面構成変更。
- Arm64版の実機動作。クロスビルドと配布ZIP生成は確認済みです。
- OSの通知領域からのメニュー開閉。メニュー部品は検証画面で確認していますが、通知領域自体は操作ツールの制約があります。
- 他アプリとのクリップボード競合、保存先の権限など、すべてのOS環境の組み合わせ。

保護された映像やセキュアデスクトップは撮影対象外です。
