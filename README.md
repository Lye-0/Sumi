# Sumi

範囲を切り取り、ローカルLLMから静かに回答を受け取るWindowsアプリ。

## 開発

Windows 11、.NET 10 SDK、Ollamaと画像入力に対応したローカルモデルが必要です。
追加のNuGet依存はありません。現在の実機検証モデルは `gemma4:12b` です。

```powershell
./scripts/dev.ps1
# ビルドのみ
./scripts/dev.ps1 -BuildOnly
# 自動検証（インストール・システム設定の変更なし）
dotnet run --project tests/Sumi.Tests
# 実際のモデルで合成画像を読み取る検証
dotnet run --project tests/Sumi.Tests -- --live
```

開発データは `.dev-data` に隔離します。Debug版を直接起動した場合は実行ファイル横の `.dev-data` を使います。
Release版の通常データは `%LOCALAPPDATA%/Sumi` です。`--data-dir <directory>` または `SUMI_DATA_DIR` で変更できます。
実行ファイルの設置先とは独立しており、設定にSumi自身の実行パスを保存しません。
インストーラー、スタートアップ登録、サービス、タスクスケジューラ、PATH変更は実装していません。

## 使い方

1. 画像への指示、モデル、回答の受け取り方を設定。
2. 表示された `ollama run <モデル>` を確認し「モデルを準備して開始」。
3. 待機中になったら、ウィンドウを閉じても利用可能。
4. `Ctrl+Alt+S`（変更可能）で範囲をドラッグ。離すと自動送信。Esc / 右クリックで取り消し。
5. 回答は小型パネル、クリップボード、または両方へ。トレイから直近の回答を再表示。
6. 一時停止・終了は設定画面またはトレイから。

設定変更は「設定を保存」で次の撮影から反映します。準備・常駐中は開始ボタンとモデル・Ollama実行ファイルの変更を無効にします。一時停止すると変更可能になり、同じモデルでも再開できます。
外観の切り替えはその場でプレビューされ、保存すると次回も復元します。
撮影ショートカットは欄をクリックして実際のキーを押して記録します（Ctrl / Alt / Shift ＋ 英数字）。Escで記録を終了します。記録中は撮影ショートカットを一時解除し、保存するまでは元の設定を使います。
秒数欄は半角数字だけを受け付け、貼り付け・IME・ドラッグからの文字混入も防ぎます。保存時には表示3–120秒、待機30–1800秒の範囲を確認します。
画像保存先・Ollama実行ファイルは「参照…」で選択可能。パス欄は1行ならコンパクトに、長い場合は折り返して伸びます。
上部の情報ボタンから、本体・設定・一時画像・保存画像・Ollamaの場所と、本体フォルダーを移す手順を確認できます。表示されるパスは現在の実行環境から取得し、本体の設置先を固定しません。
画像の保存・コピーは任意。回答のコピーと両方を有効にすると、画像の後に回答がクリップボードを上書きします。
直近の回答はメモリ内のみ。画像は既定では送信用一時ファイルだけを作り、完了・キャンセル時に削除します。

## CLI連携と制限

SumiはHTTP APIを直接呼び出しません。`ollama ls` / `show` / `run` / `stop` を使用します。
起動引数は `run <モデル>` のみで、effort / think / keepaliveを上書きしません。
入力はUTF-8の標準入力、画像は一時PNGパスで渡します。シェルは起動しません。
CLI自身はOllamaサービスと通信します。子プロセスの接続先をローカルに固定し、クラウドモデルは拒否します。
モデルの自動ダウンロードは行いません。Ollamaサービスは利用者が起動してください。

事前準備は空の標準入力を閉じた `ollama run <モデル>` です。保持時間はOllama既定値に従うため、
長時間使わなかった後は次の撮影時にモデルを再読み込みすることがあります。
終了時はSumiのCLI子プロセスを回収します。「終了」はモデルの保持をOllamaに任せます。「モデルを解放して終了」は、このSumiの起動中に準備・使用したモデル（変更前のモデルも含む）に `ollama stop <モデル>` を実行してから終了します。共有のOllama本体は終了しません。同じモデルを利用する他のアプリにも解放が影響します。トレイからも両方を選択できます。解放は合計20秒を上限とし、失敗時は再試行またはSumiだけの終了を選べます。対象モデルと実行ファイルの記録はメモリ内だけで保持します。

思考出力はCLIの `Thinking...` / `<think>` 形式を本文と分離します。詳細設定の「モデルの思考内容も表示」（初期状態オフ）で表示できます。モデルの思考設定は変更しません。未知のCLI出力形式は追加検証が必要です。
保護された映像やセキュアデスクトップの撮影は対象外。HDR環境の色再現、異なるDPIの実機複数画面は検証結果を参照してください。
ガラス調の外観はWPF内のグラデーションと半透明レイヤーで描画します。ウィンドウの背景は不透明で、デスクトップ背景のぼかしには依存しません。上部のタイトルと余白をドラッグするとウィンドウを移動できます。

Debug版の `--ui-test` は、通常タスクバーに出ない範囲選択・回答ウィンドウをUI検証ツールから列挙できるようにするフラグです。
描画・撮影・推論処理は通常と共通です。Release版では無効です。
Debug版だけは開発データフォルダーに状態・エラーの `development.log` を記録します（指示文・回答本文は記録しません）。

`IModelProvider` がモデル連携の境界です。将来のCLI実装をUI・撮影部分から分離して追加できます。
GitHub Releasesと `.github` の設定は開発完了後に整備します。Sumi専用アイコンを実行ファイル・ウィンドウ・トレイへ埋め込んでいます。

## 回答本文が空の場合

CLIが正常終了しても回答本文がない場合は、同じ画像・指示文で1回だけ自動再試行します。思考文は回答として表示しません。再試行中は状態を表示し、再び本文がない場合は原因を区別したエラーを表示します。待機上限は最初の実行と再試行を合わせた時間です。キャンセル・CLIエラーでは再試行しません。

選択問題向けの指示例：

> 画像の問題を解いてください。最終回答には、正しい選択肢の記号と語句を「(記号) 語句」の形式で1行に出力してください。説明は不要です。

2026-09-17、Ollama 0.34.1 / gemma4:12bで同じ英語選択問題を3回実行し、上記の指示で3回とも回答本文を取得しました。単一画像での少数回の結果であり、すべての問題での成功を保証するものではありません。再試行の上限・入力保持・キャンセル・短い回答の処理を含む自動チェック42項目が通過し、Releaseビルドは警告・エラーなしでした。

終了操作の追加検証：自動チェック49項目通過。ライト／ダークと幅700の実画面で赤い終了ボタンを確認し、gemma4:12bの準備→モデル解放付き終了で、Sumiプロセスの終了と ollama ps のモデル一覧が空になることを確認しました。Ollama本体は稼働を継続します。

## 思考内容の表示

設定を保存すると次の撮影から反映します。オンの場合は小型パネルと「直近の回答」に思考内容のアコーディオンを表示し、1回目と再試行を分けて保持します。回答本文がないエラーやキャンセル時も、取得済みの思考は閲覧・コピー可能です。エラー時は自動で閉じません。クリップボードのみを選んだ場合、通常の生成中にパネルは開かず、「直近の回答」で思考を確認できます。

回答が完成すると思考部分を折りたたみます。展開中・パネル操作中は自動非表示を止めます。長文は高さを制限したスクロール領域に収め、思考欄を上にスクロールしている間は末尾に追従しません。回答を取得できた場合の自動コピーと回答コピーボタンは最終回答のみです。再試行しても回答本文がなかった場合は、クリップボードを含む受け取り方であれば、最後に取得した空でない思考内容を自動コピーします（思考の表示設定がオフでも有効）。思考も空の場合は上書きしません。キャンセル・待機時間超過・CLI自体のエラーでは自動コピーしません。思考には専用のコピーボタンもあります。内容は直近1件をメモリ内に保持し、次の撮影・アプリ終了で破棄します。表示設定をオフにして保存した場合も表示用の保持内容を消去します。

追加検証：思考の抽出、2回とも本文がない場合の保持、再試行後の成功、UI部品のエラー時の表示・自動非表示・コピー制御を含む自動チェック62項目通過。Releaseビルド成功。実画面の操作確認はツールのアプリ承認待ちがタイムアウトしたため未完了です。

## 最小の通知

回答の受け取り方で「最小の通知」を選択できます。回答本文と控えめな思考アコーディオンだけを表示し、タイトル・コピー・閉じるボタンは表示しません。思考の表示は「モデルの思考内容も表示」の設定に従います。回答欄は1行なら1行分、2行なら2行分の高さで、3行以上は2行分に収めて内部スクロールで読みます。思考を展開した場合も本文は最大2行とし、続きは思考欄内でスクロールします。再試行分も同じスクロール欄にまとめるため、試行回数によって高さは増えません。通知は右クリックで閉じられます。通常は表示秒数に従って消え、操作中・思考展開中・エラー時は自動では閉じません。「最小の通知」はクリップボードの自動コピーを行いません。「最小の通知 ＋ クリップボード」は同じ最小表示に加えて回答を自動コピーし、回答本文がない場合は既存の思考コピーの動作に従います。

最小通知の追加検証：1〜3行の高さ、表示部品、コピー対象を含む自動チェック70項目通過。合成した1行回答と折りたたみ思考の実画面表示を確認しました。

## 複数画像のストック送信

モデルを準備して開始した後、Ctrl+Alt+Shift+Sで範囲選択すると画像をストックします。繰り返して撮影順に蓄積し、Ctrl+Alt+Sで必ず最後の1枚を撮影し、ストックした画像の末尾に加えて、保存済みの指示文と一緒に1回のCLI呼び出しで送信します。ストックが空の場合は、その1枚だけを送信します。最後の範囲選択をキャンセルすると送信せず、ストックを保持します。両ショートカットは設定から変更でき、同じ組み合わせは拒否します。

ストックはメモリ内だけに保持し、ストックの上限は20枚・PNG合計128MBです。送信時には最後の1枚が加わり最大21枚になります。回答取得成功時に空にし、失敗・キャンセル時は再送用に残します。一時停止でも保持し、終了または設定画面・トレイの破棄操作で消去します。設定画面とトレイのツールチップで枚数を確認できます。送信中は追加撮影・破棄を受け付けません。画像保存を有効にした場合は送信時に各画像を保存します。画像コピーを有効にした場合は最後の画像がコピーされ、回答コピーも有効なら回答取得後に置き換わります。

複数画像の追加検証：自動チェック81項目とgemma4:12bの実モデル検証1項目が通過。異なる数値の合成画像2枚を1回で送り、両方の数値の回答を確認しました。実画面でもストック用キーによる通常・逆方向ドラッグで2枚を蓄積し、旧仕様での送信キーによる一括送信、回答取得後の0枚表示、一時画像削除を確認しました。

最終撮影の追加検証：ストックの順序を保って最後の1枚を追加すること、ストックが空なら最後の1枚のみになることを自動チェックで確認しています。

## 通知領域の操作

トレイアイコンを左クリックすると設定画面を表示・復元します。右クリックはSumiのテーマに追従するメニューです。上部に状態・モデル・ストック枚数、その下に撮影操作、回答とストック、一時停止／再開と設定画面、終了操作の順にまとめています。ショートカット欄は保存済みのキーを表示します。回答なし・ストック0枚・処理中などでは対応する操作を無効にし、生成中はキャンセル、停止中は再開を表示します。メニューはEsc・外側クリック・項目選択で閉じます。

トレイ追加検証：状態分岐を含む自動チェック91項目通過。メニュー部品を検証用画面から開き、ダーク／ライトと閉じる操作を実画面確認しました。OSの通知領域自体は操作ツールで直接扱えず、実アイコンの左クリック／右クリックからの動作確認は未完了です。
